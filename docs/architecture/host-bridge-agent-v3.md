# 主机桥对齐 Agent V3（2026-10-27）

## 范围与验收

保持 /motor/*、/imu/data、/imu/temp 及 /motor/execute_config 的主机接口；
线上只注册 AgentWireContract 定义的三下行、五上行。固件协议和电机保护不变。

- command：48 台容量、1–64 ID 范围；完整快照含空快照使用 SNAPSHOT；明确停止使用 STOP_ALL/config 安全路径。
- status：拆出状态、控制授权、诊断、系统状态和轨迹进度；时钟无效状态仍可报告，但禁止新增运动。
- info：建链/修订变化主动逐页查询，整表同 revision 才发布；不把查询当成硬件回读；允许时钟无效时只读查询。
- config：统一分配递增线上请求号，缓存内容幂等；新请求逐条等待受理/拒绝后推进；终态发布与服务响应后显式 ACK；不以发送成功代替执行结果。
- policy：保持代数及每台保护确认，不自动加代数或复权；全禁用保持独立安全路径。
- trajectory：有界缓存主机分段（总 256 点），重分为32点 LOAD，等待收据推进，最后 COMMIT；空轨迹取消当前已知轨迹；会话切换/失败清缓存，不自动重播。
- temperature：sensor_msgs/Temperature 转回主机已有 Float32 温度接口。

## 实施

1. 纯消息转换：复用现有量化与分组组装器，增加V3严格字段校验、状态与info转换测试。
2. 节点适配：V3端点、分页、配置串行受理/终态ACK、轨迹请求收据闭环；更新节点集成测试。
3. 构建测试（独立ROS domain），独立审查，更新运行中的桥；仅只读Agent建链验收，不执行动作、参数写或SAVE。

## 限制

V3无历史事件流：只将明确配置/轨迹拒绝结果适配成主机事件，不虚构逐条硬件事件。
V3终点为软停，主机trajectory_state按实际终态发布active=false/completed=true，不伪报保持。
真机运动、保护和Flash验收另行授权；宿主测试不证明USB最大负载下时延。

实际源码核查：V3 motor_id=1..64；旧桥0..63判据错误。本次扩共享组装器索引缓存至65，新V3入口拒绝0。

安全适配：桥在轨迹装载时屏蔽该轨迹电机仍在重复的原快照目标，防止终点软停后自动回到起点。
更改目标值是新意图，显式取消也会释放屏蔽；重复相同旧目标不恢复运动，需要先明确取消。
LOADING/READY 不冒充主机正在执行的轨迹；主机轨迹流从 RUNNING 或终态开始发布。
页面先判断 completed，再判断 active=false 的取消语义，不把V3成功终态当成失败。
参数分页刷新保留已验证的身份表，避免仅查询参数就打断30ms运动租约；会话/电机集合变化才撤掉旧门禁。

审查修复：已发送配置的服务等待超时返回 STATUS_PENDING/error_code=21，表示结果未知，
不伪报设备失败或回滚；桥保留最多8项请求关联且停止重试过期请求，晚到实际终态仍按原
调用方请求号发布，随后才ACK回收。未发送请求的源有效期过期可以确定为本地失败。
