# 激活失败与回环终止采用 fail-fast 语义

> **当前适用性（2026-09-11）：有效。** 真机激活/反馈超时和仿真关键进程退出继续采用 fail-fast；正文中的 `driver_loopback` 是历史入口名，不表示当前四轴 Gazebo 已与 `motor_sim` 完成联动。

**Status**: accepted

驱动侧硬件激活失败或运行期反馈超时会让 `controller_manager` 进程立即终止（Humble
`resource_manager` 的默认行为）。这是预期的安全语义：电机不可达就不能运行，人工
诊断后重新 bring-up。**激活阶段允许有界重试**：每次尝试在 `initial_feedback_wait_s`
（默认 1 s）窗口内轮询全部关节反馈，连续 3 次未收齐才判定失败并抛出异常；
运行期反馈超时不做重试，直接终止。仿真回环的启动竞态由 launch 时序消除（模拟器
就绪后才拉起驱动侧）；模拟器退出时 `driver_loopback` 整个终止并给出可操作提示，
避免 spawner 无限重试。

## Considered Options

- **无限重试/自动重启（模拟器 respawn、无界激活重试）**：会掩盖“电机真的连不上”
  或“vcan 未创建”这类根因，且安全系统失败应快而可预测，故否决。
- **激活阶段有界重试（已选）**：最多 3 次、每次 1 s，容忍上电初期总线/电源时序
  抖动；仍失败则立即 fail-fast，不掩盖根因。
- **fail-fast（已选）**：失败立即暴露，重跑前先诊断；回环额外把“模拟器退出”
  转化为整个 launch 的终止。

## Consequences

- 真机：激活 3 次仍失败或运行期反馈超时 = 安全停机信号，人工排查总线、电源、
  标定后重跑；激活日志以中文打印缺失反馈的关节清单。
- 回环：vcan 未创建等启动期错误会在模拟器退出时终止 launch 并打印提示；
  运行中模拟器掉线同样终止回环，不会静默挂死。
