# Web 上位机采用 A 布局与 Vue 外壳

**Status**: accepted（2026-10-23）；取代 ADR 0010 的无构建链与外壳实现选择。

## Context

用户确认真机调试、动作和仿真/HIL 同等支持，并在交互原型中选择 A 均衡工作台。
参考资料见 [机器人工作台研究](../research/robot-console-workbench-reference.md)。
已有原生面板覆盖参数事务、动作分窗播放、重力前馈与台架编排；重写外观时同时复制这些
协议逻辑会引入两套行为。原生共享 store 与连接模块应在迁移期间继续作为唯一状态来源。

## Decision

1. `web_host/frontend/` 使用 Vue 3、TypeScript、Vite；构建产物进入 `web/workbench/`，
   仍由 Python 静态服务托管。Node 只参与开发和构建，运行时不增加 Node 服务。
2. 采用 A 布局：左侧对象、中间场景、右侧检查器、底部观察区。真机、动作、仿真/HIL
   为三个同级工作视图；视图切换不改变 ROS 会话，不发控制消息。
3. `runtime.ts` 是迁移适配器：复用 `web/js/core/` 与 `web/js/panels/` 的通信和领域行为，
   Vue 外壳只读取类型化快照和调用显式操作。不得在 Vue 再维护一份电机/参数事实。
4. 每个原生面板只挂载一次；切换视图和检查器页签通过隐藏处理，保留输入草稿。
   调度器为每个面板累积脏标记，隐藏和节流均不能丢掉一次性的参数或事件更新。
5. 所有面板完成挂载后才连接 ROS，避免首帧参数报告先于承接 DOM。命令、策略、参数面板
   初始化失败时禁止连接；其他面板失败就地呈现、相互隔离。渲染失败保留脏标记并有限重试。
   卸载取消渲染和自动重连，不自动发运动命令。
6. 模型设备映射只接受当前模型响应；失败时清空，不沿用默认或上一模型的映射。
   URDF 关节、TF 数据与电机测量保持不同来源语义。
7. 根入口转到已构建的 `/workbench/`；经典界面仍由 `/index.html` 提供，面板模板仍以
   经典页面为唯一宿主。`prototype/` 只供历史比较，不安装为工作台，也不作为生产控制源。
8. 使用 Vitest 验证调度、清理与映射行为，用 Playwright + 假 rosbridge 验证实际模块组合。
   保留现有静态契约及文件 API 测试。自动测试不启动 Agent、仿真或真实设备。

## Consequences

前端源码变动需要先执行 `npm run build` 再安装 ROS 包；缺少构建产物时安装明确失败。
生成资产不入版本库，部署需携带完整 `web/`，包括原生模块、模板与 vendor。

迁移适配器包含原生 DOM 依赖；Vue 与原生面板不得共同修改同一片 DOM。
后续替换面板时必须一并迁移对应领域行为与测试，再删除旧实现，避免长期双写。
当前选择提供新的工作区结构和类型化外部接口，不表示所有面板内部均已改写为 Vue。

本决策不改变 `bench_manager`、`command_streamer`、ROS 话题、消息或固件控制职责。
WebSocket 连接、Agent 进程、固件数据新鲜度与命令实际输出分别显示，不能互相替代。
动作播放绑定连接代次，断线或换连接使旧播放失效，重连后必须由操作员重新发起播放。
