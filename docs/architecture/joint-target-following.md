# 滑块连续目标跟随

2026-11-02，用户确认滑块采用连续跟随，JTC 保留用于动作播放。

## 约束与接口

- 上位机目标与 MCU 反馈各 50 Hz，MCU 电机执行 200 Hz 不变。
- 滑块经 `/control/joint_target`（`sensor_msgs/JointState`，非空唯一 name、对应有限 position，velocity/effort 为空）提交最新位置。header 是输入新鲜度，不是轨迹执行起点。
- `workbench_control` 校验模型、实测、原始时间、限位和停止屏障，互斥切换到 `follow_controller`，忙时只保留一个最新目标；不把拖动排成动作队列。
- 内部跟随目标在控制器确认 active 后发送，控制器只接收本次激活后的消息。内部命令话题不开放网页写入。
- 插值在 ros2_control 的 50 Hz update 中执行。从上一周期指令 P/V 生成解析梯形速度段，速度上限沿用 URDF；加速度上限为速度上限 / 0.5 s。连续改目标保持指令 P/V 连续，松手后到达最后目标并保持。
- 首次激活从真实测量保持开始；停止、断连、切换或重新激活清除目标。现有 MCU 断流停止、主机位置/速度限位及 0.1 rad 跟随误差保护保留；不调整电机增益或保护参数。
- JTC 动作路径保持独立，不因滑块目标重建 JTC goal。

## 重力补偿开关（2026-11-03）

- 3D 底栏提供显式开关，复用 `/bench/start_gravity_feedforward` 和 `/bench/stop_gravity_feedforward`；开启按 1.0 系数补偿，只写重力参数，不自动使能电机或发送运动目标。
- 连续跟随与 JTC 均只占用 P/V，`gravity_controller` 独占 E，并与对应运动控制器一起激活和停止；关闭补偿时 E 为零。任一模式所需控制器异常退出时，停止整个主机控制会话。
- 保留完整模型姿态、传动组、反馈新鲜度、参数回执和实际状态回读校验。当前两电机子集不具备完整模型反馈，拒绝启用；不补造缺失关节角，不修改已校准模型或保护参数。
- 网页不保存或自动重放开关；未知/断连/模型不匹配不得显示已生效。服务受理后等待主机回读，失败或超时显示原因。
- 停止运动保留当前主机会话的重力配置，显示「已开启 · 待运动」；只有下一次显式运动启动后才显示「补偿中」。管理器状态超过 2.5 秒失效，不能用陈旧 pending 掩盖超时错误。
- 验收覆盖 P/V/E 接口无冲突、连续跟随与 JTC 切换、任一控制器故障后的停止、开关受理/拒绝/超时/断连与模型切换。仅进行隔离测试与现场只读检查，不代操作真机补偿。
- 本轮定向验证通过：142 项网关/launch、56 项管理器、20 项前端单测、7 项浏览器测试，以及跟随/速度规划/重力三个 C++ 测试组。独立审查发现的陈旧 pending 提示问题已修复并复核。软件已安装，重启主服务并恢复原 Agent；部署后 8 秒只读采样 MCU 回传 50 Hz、执行频率回读 200 Hz、无运动授权。电机仍离线，未验证实际补偿力矩。证据在 `/home/ly/robot2_ws-checkpoints/20261103-gravity-toggle/`。

## 验收

核心先补回归：连续目标不产生 JTC goal；快速反向时每周期 P/V 有界且保持连续；最终到位保持；无效/过期目标拒收；停止与迟到消息不能恢复旧运动；重激活仅从实测开始；真实跟随误差仍触发停止。

运行相关控制器、主机网关、launch 与网页定向测试，并做一次独立审查。部署前确认无运动授权；仅重载相关主机服务，随后只读观察两个关节反馈，不代操作真机滑块或使能。

现场曾见拖动 goal 受理后速度指令越 URDF 限位，继而硬件接口撤销与反馈会话重建。相关历史日志已从 journal 归档到 `/home/ly/robot2_ws-checkpoints/20261103-joint-follow-verify/previous-feedback.log`。重建阶段控制状态超时原因仍需独立复现；不得通过放宽新鲜度窗口掩盖。
