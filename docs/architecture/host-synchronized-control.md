# 主机控制与同步时间

主机控制器以 50 Hz 输出目标。MCU 运动反馈携带同步时间、会话标识和测量年龄，主机据此判断反馈是否可用。状态、运动反馈和 MCU 执行频率见[通信时序](microros-timing.md)。

## 策略提交

网页通过 `/motor/submit_policy` 提交电机策略、当前 MCU 会话和最近收到的 MCU 源时间。Bridge 生成策略代数与请求标识，浏览器使用返回的意图标识关联服务响应、配置回执和 MCU 状态。

Bridge 校验会话、源时间及停止屏障。排队和等待授权沿用请求原始时间。使能成功需要 MCU 回执和相应代数的实际状态，随后才接受运动目标。失能和停止保留独立入口。

停止、断连、会话变化或请求过期会终止相应意图。重连和反馈恢复后，操作者需要重新使能并提交目标。`/motor/policy_array` 保留给已有外部客户端，网页使用服务入口。

## 时间与授权

主机检测墙钟相对单调钟的跳变，MCU 检查校时健康。两端的跳变容差和消息未来偏差上限均为 20 ms。

运动命令与授权租约分别计时。有效 SNAPSHOT 可续租已有授权，空闲期由 AUTHORITY 保活。MCU 使用单调截止时间处理命令过期，后续校时或保活不会延长已接收目标的执行期限。

请求关联使用意图标识与策略代数。同步时间可能发生校正，不能独自充当唯一请求标识。历史测量数据见[同步测量报告](../outputs/2026-11-02-clock-sync/report.md)。

## 代码与测试

- `ros2_ws/src/micro_ros_bridge/src/bridge_node.cpp` 处理策略服务、授权与停止。
- `micro_ros_firmware/lib/control/src/agent_protocol.c` 校验会话、序号和截止时间。
- `ros2_ws/src/web_host/web/js/core/control_policy.js` 关联网页意图与 MCU 回执。
- 桥接测试覆盖相同时间戳的并发请求、迟到回执、停止屏障、过期、重连和失能。前端测试覆盖回执绑定、连接变化和状态新鲜度。
