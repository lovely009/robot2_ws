# URDF 与 STL 联合核对（2026-11-05）

对象：`trial_arm_7dof/urdf/trial_arm_7dof.urdf` 与运行目录下8个原始STL。全部关节取q=0，按 `T_base_child = T_base_parent · T_joint_origin` 装配；URDF RPY采用固定轴XYZ，即矩阵Rz(yaw)Ry(pitch)Rx(roll)。所有量化计算使用完整网格。

**结论：资源、单位量级和文件适配没有发现问题；几何轴线核对发现J2、J3、J5三处显著不一致。当前模型不应仅凭TF树和惯量正定检查就视作运动学已验收。** 本次只核对和记录，未修改URDF、STL、控制配置或原始CAD。

## 1. 资源与坐标检查

- 8个link、7个revolute关节，唯一根base_link；父子树连通、无重复子节点和环。
- 16个visual/collision网格引用全部可解析，大小写和路径匹配。每个link的visual与collision引用同一个STL，局部origin均为零，scale默认为[1,1,1]。
- 运行STL逐字节等于保留的CAD原件。关节parent、xyz、rpy和axis与原始CSV一致；此次更名适配没有引入几何变换差异。
- STL为有效二进制三角面数据，头部面数与文件长度一致，全部顶点有限，没有零面积三角形。STL自身不声明单位；数值按米使用，与关节尺寸和已识别的直径58mm电机圆边界一致，未发现1000倍缩放错误。
- 零位整体包围盒约91×147×1028mm（包含支架）。当前CAD零位中手臂朝上延伸，不等同于编码器零位或常用垂臂姿态。

圆边界由现有 `half_body_robot/tools/build_motor_frames.py` 的 `circles()` 提取；从三角面共面边界拟合圆心和法向。它提供几何证据，不替代实机装配图对零件功能的确认。选中特征的半径拟合残差小于0.0001mm，以下毫米/角度级差异远大于拟合和导出舍入误差。轴向比较使用夹角绝对值，不把法向正负号误当180°错位。

### J2：几何铰孔对得上，URDF转轴偏了5mm

父link1圆孔/轴承边界中心线约为局部 x=5mm、z=20mm，沿Y。URDF的J2原点却是局部[5.1132,0.5,15.001]mm，其轴与Y平行。
子link2两侧圆孔中心约为[-0.11319,4.99871,±27]mm，沿局部Z；URDF轴经过子坐标原点。
变换到base系，两侧几何轴在关节附近相差约0.000294mm、方向差0.000211°，可认为在导出精度下吻合，但两者都距URDF轴约5mm。
这说明零位外观可以装配对齐，而按当前URDF旋转时会绕偏置轴运动。关节2采用位置控制并不能消除这种运动学偏差；此前只排除了它的质量验收要求。

### J3：中心对齐，法兰方向不一致

父link2法兰圆心约[33.61967,39.27109,0]mm，局部法向约[0.99974377,0.02263604,0]。
子link3原点处直径58mm圆边界法向沿局部Z；它与URDF轴方向吻合。
父法兰几何轴与URDF轴夹角2.59152°，两圆心附近轴线位置差不到0.001mm。应回查原装配配合和Coordinate_system3/Axis3的朝向；仅把整条链平移无法消除该角度差。

### J5：两侧实体安装轴吻合，URDF原点和轴方向均偏离

父link4若干同轴圆边界沿局部Y，中心线约x=0.005657mm、z=-23.5mm。
子link5安装圆中心约[0,-4.27358,-0.27825]mm，法向约[0,-0.0431752,0.9990675]。
在base系，两条几何轴在关节附近距离约0.000038mm、方向差0.000441°。
但URDF的J5原点距几何轴约4.2816mm，其局部axis=[0,0,-1]与几何轴相差约2.4745°～2.4750°。
应回查Coordinate_system5/Axis5以及关节原点。不能只改axis而忽略偏心，也不能只挪origin而使网格、质心及下游关节坐标失去一致性。

当前collision直接复用全部外观网格，且关节上下限仍为零，本次没有进行全行程碰撞检查。若后续用于物理仿真，需在运动学修正后另行准备碰撞体与允许接触关系。

本次URDF/STL哈希与上次复核对应，先前3～7质心位于网格凸包内、惯量必要条件通过的结论仍成立；J7在均匀密度假设下约37%～38%的惯量匹配疑点也仍存在，见 [质量属性复核](../inertial_audit/2026-11-05-recheck.md)。
