# CERB 厂商问题清单（待外部确认）

状态：开放，待厂商 / 手册答复。日期：2026-09-19。

下列问题在四份文档（R48/R58 规格书 + CANopen 字典表 + 说明书）中**均无定义**，
只能问厂商或等真机到货做台架反推。第 1 条是「固件静态参数扩容序列」第 1 项
（MIT 全量程核验）的阻塞项，见 `w25-blob-v3-design.md` §11。

1. **MIT 帧（`0x110|id`）的 `Pos Max` / `Vel Max` / `T_Max` 分别取自哪个对象或
   常量？** 是否随 `0x607D` / `0x6080` / `0x2538` 的写入而改变？量纲与满量程值
   是多少？（四份文档中这三个量仅出现在 MIT 字节表内，均无定义。）
2. **`0x2531` 的读回语义是什么？** 字典范围 0~2 中 "2" 代表什么？（手册"标定复位
   指令"与"标定指令"给了同一串 hex，疑为抄漏。）
3. ~~**`0x2650:01` 的读子索引是不是 `0x01`？**~~ **已结案（2026-09-19）**：读子索引是 **`0x00`**；`:01`/`:02` 回 ABORT `0x06090011`（子索引不存在）。对象语义经 owner 手工核实：读 `40 50 26 00 00 …` → 反馈 `43 50 26 00 0x …`；`23 50 26 00 **00** …` = **开启**保护、`23 50 26 00 **01** …` = 关闭。台架四台上电初值均为 `1`（关闭）。**无需再问厂商。**
4. ~~手册"读取正限位 / 读取负限位"两行的子索引与设置行**相反**，是否为笔误？~~
   **已结案（2026-09-21）：是笔误，固件方向正确，无需问厂商。** 三条互相独立
   的证据同向，且笔误本身自相矛盾（照它读 `:01` 会读回 **-32568**，一个负数
   不可能是"正限位"）：
   - 手册**自己的设置行**：`23 7D 60 02 30 7F 00 00` = 设置正限位（值 +32560）、
     `23 7D 60 01 C8 80 FF FF` = 设置负限位（值 -32568）——与字典表同向；
   - 《CANopen 字典表》：`:01` = 下限、`:02` = 上限；
   - 真机四台只读 SDO（2026-09-19）：`:01` = **-32768**、`:02` = **+32768**
     （`docs/reports/2026-09-19-cerb-real-hardware-bench.md`）。
   固件（`kStagesPositionLimits` / `kStagesRefresh`）与 `cerb_adapter.c` 顶部注释、
   `test/host/test_motor_protocol_adapter.cpp` 的字节断言均已锁死该方向；
   反向修改会**真的把限位写反**（设备侧限位保护按错误的边界执行）。
5. ~~**`0x2541`（电机方向定义）的写路径与取值范围？**~~ **已结案（2026-09-20，
   owner 手工核实）**：写命令 **`23 41 25 00 0X 00 00 00`**（`0X` = 0 → CW、
   1 → CCW），读 **`40 41 25 00 00 00 00 00`**；取值范围 0/1。**掉电不保存**
   （与 `0x2650:00` 同形），所以固件在**上电归一**里按 W25 记录写回。已进参数面
   （`m<id>.direction`，原值直通），写事务 = 写 + 读回核验，仅未运动时受理。
   **仍待台架实测**：这条命令的写入是否被设备接受、以及易失性对照
   （`tools/cerb_sdo_probe.py --write 0x2541:00=1` → 断电 → 读回应回 0）。
6. ~~**`0x2650` 对应的 `0x2539` 保存码是哪个？**~~ **已作废（2026-09-19）**：
   不需要保存码。官方 §4.11 明确码 `1` = 保存 "PI 参数和最大电流"，不含
   `0x2650`；实测也印证掉电不保存。**该设置易失**，要"保护必须开着"须每次
   上电显式发一次 `23 50 26 00 00 …`。
7. ~~规格书"位置环编码器 21 bit"与说明书"负载端 16 bit（65,536/圈）"如何对应？
   线上位置是否为 ±32768 cnt ↔ ±180°（182 cnt/度）？

8. **MIT 模式下驱动器内部如何处理 setpoint？** 固件把 CERB 钉死在 MIT
   （`SET_MODE` 对 CERB 是空阶段，`lib/motor_protocol/src/cerb_adapter.c:829`），
   **从不使用**字典表里的 `0x6060` = 8/9/10（周期同步位置/速度/电流——那三个才是
   自带插值语义的模式）。已确认看门狗要求数据帧间隔 < 500 ms，故推断驱动器是
   **保持最后一个 MIT 目标**（零阶保持）并按内部环运行。需厂商确认：
   （a）MIT 目标是否零阶保持？（b）内部是否还有轨迹发生器/插值？
   （c）电流环与位置环的内部频率各是多少？
   这三条仍值得问清——它们决定**命令率再往上的收益边界**。
   **但"要不要 200Hz"本身已不由它们决定（2026-09-21，owner 裁定）**：驱动器与
   固件的命令频率 **200Hz 是底线**，固件按此实现（控制边界逐边界发帧，见
   `motor_control_hold_step`），不再等厂商答复。原先这里写的"在此之前不应为
   '走不顺'去提频"作废：当时把 50Hz 当作待证口径，现已明确不是。
   提频的可行性算式见 `48-motor-scale-design.md` §3.2（4.35% @4 台 / 26% @16 台
   每总线）。

+ SDO 读，不烧板子、不改设备），真电机到场后一次性反推第 1 条。
