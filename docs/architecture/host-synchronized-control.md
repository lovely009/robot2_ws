# 主机统一时间与 50 Hz 控制流

2026-11-02：用户同意使用统一同步时间，控制目标通信 50 Hz，时间容差上限 20 ms。

## 约束

- 主机目标流和电机反馈保持 50 Hz（20 ms 周期）。独立授权心跳也是 50 Hz，两类消息不等于合计每秒只有 50 帧。MCU 内部控制环和 IMU 采样频率不跟随降低。
- 主机与 MCU 统一时间域；主机墙钟相对单调钟的跳变容差收紧至 20 ms，与 MCU 当前校时跳变门一致。消息允许的未来偏差仍为 20 ms。
- 动作下发和维护请求也使用已收到的 MCU 同步源时间，不再取浏览器墙钟；无源时间拒发非空动作及维护写入。REPORT、取消和 STOP 保留不依赖时间的旁路。原有请求号和轨迹号仅用于关联，不作为时钟或授权事实。
- 20 ms 是时间异常阈值与控制周期，不是已证明的绝对同步精度，也不作为断流停止门限。源命令 30 ms 截止、30 ms 软停、100 ms 撤权及现有租约、限位和设备保护保留。
- 不刷新旧请求的源时间，不因 RPC 失败、重连、校时恢复而自动重新使能。

## 最小实施

1. 新增仅用于主机的 `/motor/submit_policy` 服务。网页只提交目标、当前 MCU 会话以及最近一次 MCU 同步状态的源时间，不再分配策略代数。
2. Bridge 校验原始源时间与停止屏障。等待授权或排队时，100 ms 策略 TTL 从该原始时间计算，不能用回调执行时间重新盖章。
3. 主机生成带实例隔离的同步时间意图标识，以字符串完整传回浏览器；内部代数超过本地高水位、MCU 停止屏障和全部电机已见代数。内部请求号由 Bridge 单点分配。
4. `ConfigResult` 回带同一意图标识。使能需要本意图的成功回执，以及 MCU 精确代数、活动状态、在线与新鲜反馈，才能发送动作。仅受理 RPC 不代表 MCU 已使能。
5. 全失能保留旁路和状态确认，不要求更新代数或成功 ACK。停止、过期、换会话不得静默遗失已受理的使能意图；并发新请求可明确返回忙。
6. 网页关闭直接 policy topic 写入，改用服务；主机保留旧 topic 的外部兼容入口。MCU 的 `Agent*` 线上消息、固件与保护逻辑不变，因此无需烧录。

## 验收

先验证服务回归：跨客户端、相同时间戳、停止前旧请求、租约等待过期、会话/主机实例变化、代数与请求空间耗尽和失能旁路。网页验证精确意图/回执/代数绑定、陈旧反馈、迟到服务响应和无自动重试；时钟验证 ±20 ms 边界与越界。隔离 ROS 域运行控制测试，不向真机发送使能或目标。

构建后更新主机服务与页面，仅做只读就绪核对。真机使能与运动仍由用户操作；这次主机修改不需要固件烧录。

实测依据见 [同步测量报告](../outputs/2026-11-02-clock-sync/report.md)：180 秒内同步健康，但存在负校正，不能用裸同步时间替代唯一请求身份。
