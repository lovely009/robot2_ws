# CERB 关节模组设备侧参考（对象字典 / 帧 / 故障码）

**Status**: 当前（2026-10-22）。**参数以厂家文档为准**；与实测不一致处集中在 §10，不在正文里改写。

本文是 CERB（巨蟹智能关节模组）**设备侧**行为的唯一宿主：对象字典、SDO 语义、反馈/控制
帧、故障码与保护逻辑。它是 `motor_drive` 的 `cerb` 协议实现、固件 `cerb_adapter`、
`micro_ros_agent` 的 FDCAN 模拟器与取证探针的共同对端事实来源。

**不写在这里的**：机器人自有的电机拓扑与型号参数（宿主 `motor_hardware_interface/config/*.yaml`）、
模拟器自身的默认值与配置（宿主 `motor_sim`）、固件如何消费这些字节（宿主
`micro_ros_firmware/README.md` 与 `motor-runtime-decision-log.md`）。

厂家参考资料原件在 [`motor_sim/docs/`](../../ros2_ws/src/motor_sim/docs/)（PDF，不改内文），

## 2. 上电与通信基线

模组上电流程（PR0002 §1）：

1. 进入 Boot 程序，约 300 ms 后跳转 App；App 初始化约 2 s；
2. 初始化完成后设备上传一帧 **`0x700 + Dev_ID`、数据 `00`**（CANopen boot-up）；
   **同时看门狗上电自锁**；
3. 电机上伺服后需延时 100 ms 再向新位置转动；
4. **看门狗数据帧间隔必须 < 500 ms，否则电机自锁**；
5. 抱闸打开与关闭各约 100 ms 延时。

| 项目 | 值 |
|---|---|
| 协议族 | CANopen CiA 402（DS402） |
| 设备 ID | `0x01`–`0x7F`（写入对象 `0x2530`） |
| CAN FD 出厂配置 | **标准帧**；仲裁段 1 Mbps、数据段 5 Mbps、数据段加速（BRS）开启 |
| 位率改写 | `0x2540:00`：0=Classic 500K，1=Classic 1M，2=FD 1M/1M 不启用 BRS，3=FD 1M/2M 启用 BRS，4=FD 1M/5M 启用 BRS。写后存 BootPublic，**复位/重新上电才生效** |
| 终端电阻 | 总线物理两端各 120 Ω，健康网络约 60 Ω |

> 设备只认**标准（11 位）帧**。用扩展帧发同 ID 的帧时设备照样在 ACK 槽应答（错误计数不涨），
> 但按 ID 过滤后直接忽略——表现为"总线健康、设备不响应"。踩坑记录见 §10.3。

## 3. SDO

从站请求 `0x600 + Dev_ID`，从站响应 `0x580 + Dev_ID`，DLC 8。索引低字节在前。分段上传
的 7 字节段载荷见 §3.2。

### 3.1 命令字

| 命令字 | 描述 | 方向 |
|---|---|---|
| `2F` | 写 1 字节 | 主 → 从 |
| `2B` | 写 2 字节 | 主 → 从 |
| `27` | 写 3 字节 | 主 → 从 |
| `23` | 写 4 字节 | 主 → 从 |
| `60` | 写数据反馈 | 从 → 主 |
| `40` | 从对象读取数据 | 主 → 从 |
| `4F` / `4B` / `47` / `43` | 读到 1/2/3/4 字节 | 从 → 主 |
| `41` … `60`/`70` 交替 | 分段上传发起 / 取段 | 从 → 主 / 主 → 从 |
| `80` | 中止，后 4 字节为中止码 | 从 → 主 |

中止码实测（§10.1）：**对象不存在 → `0x06020000`；子索引不存在 → `0x06090011`**。
两者必须区分——设备本身是区分的。

### 3.2 常用事务（PR0002 §4）

| 用途 | 请求（`0x600+ID`，DLC 8） |
|---|---|
| 厂家名称 `0x1008:00` | `40 08 10 00 00 00 00 00`（分段，回 ASCII 串） |
| 固件版本 `0x100A:00` | `40 0A 10 00 …`（分段） |
| 硬件版本 `0x1009:00` | `40 09 10 00 …`（分段） |
| 读取电机实际位置 `0x6064:00` | `40 64 60 00 …` → `43 64 60 00 LL HH …`，位置**低字节在前**，**÷182 = 度** |
| 读取当前错误码 `0x603F:00` | `40 3F 60 00 …` → `4B 3F 60 00 LL HH …` |
| 读取最近故障诊断 ID `0x4500:00` | `40 00 45 …` → 低 16 位 `0xHHLL`，`HH`=故障域、`LL`=子项 |
| 设置零位 `0x2531:00` | `23 31 25 00 01 00 00 00`（**须失能**；只等写应答，不读回） |
| 修改设备 ID `0x2530:00` | `23 30 25 00 <id> 00 00 00` |
| 关闭看门狗 + 限位保护 `0x2650:00` | `23 50 26 00 01 00 00 00`（`00` = 开启保护） |
| 设置心跳时间 `0x1017:00` | `2B 17 10 00 D0 07 00 00`（= 2000 ms，**断电恢复默认**） |
| 保存到 Flash `0x2539:00` | 保存码：`1` = 电机参数（最大电流/最大转速/PI），`2` = 正限位，`4` = 负限位 |
| 恢复默认参数 | `0x1011:03` |

限位的读写子索引：**设置正限位写 `0x607D:02`、设置负限位写 `0x607D:01`**；上限 `:02`、
下限 `:01`。PR0002 的"读取正/负限位"两行与它自己的设置行相反，**以设置行为准**（§10.2）。

## 4. 执行器反馈帧

`0x300 + Dev_ID`，FD + BRS，DLC 12。**三种触发方式**：上位机发同步帧 `0x080`；执行器多控
报文触发；单轴控制报文触发。

| 字节 | 长度 | 字段 |
|---|---|---|
| `[0..1]` | 16 bit | 负载端实际位置，**Byte[0] 高 8 位**，`-32768..32767` ↔ `-180..180 deg`（÷182） |
| `[2..3]` | 16 bit | 电机端实际速度，int16，RPM |
| `[4..5]` | 16 bit | 实际电流 Iq，int16，**每码 20 mA**（手册写 mA/1 mA，实测不符，见 §10.5） |
| `[6..7]` | 16 bit | 错误代码（见 §6） |
| `[8..9]` | 16 bit | 电机线圈温度，int16，**0.1 degC** |
| `[10]` | 8 bit | 项目模式反馈：`01` 轮廓位置 / `02` 轮廓速度 / `03` CSP / `04` CSV / `05` 电流 / `06` MIT / `07` 力矩传感器闭环 |
| `[11]` | 8 bit | 状态位，见 §5 |

PR0002 的解析样例：`09 E1 FD E5 FF 51 00 00 00 F0 01 C0` → 位置 0x09E1=2529→13 deg、
速度 -539 RPM、电流 Iq 码 -175（实测刻度 20 mA/码 ⇒ -3.5 A）、无报错、温度 24.0 degC、
模式 `01`、`C0` = 上使能 + 抱闸释放 + 正常 + 运行中。

## 5. 状态位 `data[11]`

| 位 | 含义 |
|---|---|
| bit7 | 使能状态：0 下使能，1 上使能 |
| bit6 | 抱闸状态：0 抱闸吸合，1 抱闸释放 |
| bit5 | **报错状态：0 正常，1 报错** |
| bit4 | 位置到位：0 运行中，1 运行到位 |
| bit3..0 | 预留 |

## 6. 控制报文入口

| 入口 | CAN ID | 线上字节数（DLC 码） | 说明 |
|---|---|---|---|
| PDO4 / MIT 固定通道 | `0x500 + Dev_ID` | 8（8） | 维护参考，非本工程 MIT 快控入口 |
| MIT 单轴快控 | `0x110 \| Dev_ID` | 12（9） | 节点限 1–15；Byte0 控制字，Byte1–8 为 MIT，Byte9–11 补零 |
| MIT 多轴快控 | `0x210` | 64（15） | 最多六个 9B 槽位，节点范围 1–127 |
| 同步帧 | `0x080` | — | 触发反馈上报 |

依据厂家 [CANFD MIT 快控档位与缩放使用指南](../../ros2_ws/CANFD_MIT快控档位与缩放使用指南.md)：
五项缩放均参与命令量化，不能将旧 MIT 示例的固定增益刻度沿用到新设备。

| 字段 | 维护对象 | raw 位宽 | 厂家默认量程 |
|---|---|---:|---|
| P | `0x2542:00` | 16 | ±3.14 rad（对象原值 ×0.01） |
| V | `0x2543:00` | 12 | ±3.14 rad/s（对象原值 ×0.01） |
| Kp | `0x2544:00` | 12 | 0–2500 Nm/rad |
| Kd | `0x2545:00` | 12 | 0–500 Nm·s/rad |
| T | `0x2546:00` | 12 | ±300 Nm |

编码按范围钳位后四舍五入，再限制到 raw 位宽。物理零点对应 P/V/T 的 raw
32768/2048/2048，五个 raw 全零是无效载荷。控制字正常使能为 `0xCC`、失能为 `0x0C`；
bit5 清错只作为事件，不在普通控制帧中持续置位。

多轴槽位起点为 Byte0/9/18/27/36/45，各 9 Byte；Byte54–55 保留，Byte56–61 为对应
NodeID（0 表示空槽），Byte62–63 保留。保留字节补零；单轴 ID 的 `|` 不得替换为 `+`。
这些对象只说明缩放含义，本次修正不增加运行时寄存器读写或自动改写设备量程。

`6060h` 写入值兼容 CiA402 常见模式编号，设备内部映射成"项目真实模式"，`6061h` 与反馈
Byte10 显示的是**转换后**的值：

| 写入 `6060h` | 兼容含义 | 项目真实模式 |
|---|---|---|
| 0 | 无模式 | 0 不进入运动模式 |
| 1 | Profile Position | 1 轮廓位置 |
| 2 / 3 / 9 | Velocity / Profile Velocity / CSV | 2 轮廓速度 |
| 4 / 10 | Profile Torque / CST | 5 电流 |
| 5 / 6 / 7 | 项目原生电流 / MIT / 力矩传感器闭环 | 5 / 6 / 7 |
| 8 | CSP | 3 CSP |

## 7. 故障码

### 7.1 旧版兼容码（反馈帧 `data[6..7]`）

| 码 | 内容 | 触发条件 | 保护方式 | 清除方式 |
|---|---|---|---|---|
| `0x0001` | 过压 | 母线电压 > 72 V | 一般保护 | 重启清除 |
| `0x0002` | 欠压 | 母线电压 < 40 V（硬件欠压保护 35 V） | 快速保护 | 重启清除 |
| `0x0004` | 过温 | 线圈 NTC > 95 degC 持续 100 ms，或驱动 NTC > 100 degC 持续 100 ms（>80 degC 起上升斜率保护） | 一般保护 | 恢复到 85 degC 以下后指令清除 |
| `0x0008` | 堵转 | Iq 达到/超过设置最大电流持续 2 s | 限幅保护 | 重启清除 |
| `0x0010` | 过载 | Iq 电流积分大于设置阈值 | 一般保护 | 重启清除 |
| `0x0020` | 速度跟踪误差过大 | 期望与实际速度差 > 320 RPM 持续 20 ms（R120/R120MAX；其他模组 200 RPM） | 快速保护 | 重启清除 |
| `0x0040` | 正限位保护 | 限位光电开关触发，或超过软件角度限位且目标速度朝限位方向 | 快速保护 | 指令清除，反方向可运行 |
| `0x0080` | 负限位保护 | 同上（负向） | 快速保护 | 指令清除，反方向可运行 |

软件限位默认参数：正 `32767`、负 `-32767`（实测见 §10.4）。

### 7.2 V2.0 诊断 ID

支持 V2.0 的固件用 32 位诊断 ID 编码（`0xDDSS`：`DD` 故障域、`SS` 子项）。可经 SDO 读低
16 位：`0x603F:00` = 当前活跃/实际发送的错误码，`0x4500:00` = 最近一次告警/故障。部分产品
把多个新版故障折叠到同一个旧兼容码。**协议层只产出码值，不做语义解释**——解释归上游。

## 8. 保护逻辑

- **看门狗**：数据帧间隔 > 500 ms 电机自锁；上电即自锁。由 `0x2650:00` 控制：`0` = 看门狗 +
  限位保护生效，`1` = 关闭两者。**易失**，掉电回上电初值，`0x2539` 保存码对它无效。
- **限位保护**：设置限位时电机应处于失能状态，设置后需保存到 Flash。
- **抱闸**：打开/关闭各约 100 ms 延时。
- 故障项控制（TN0002 §5）：`0x2654:00` 支持故障项屏蔽/使能、故障参数覆盖清除与持久化；
  `0x1011:03` 恢复默认参数；标准 CANopen NMT 指令可复位指定节点 MCU（走通用安全复位流程，
  不立即重启）。
- 版本读取（TN0002 §6）：`0x1008:00` 设备名、`0x1009:00` 硬件版本、`0x100A:00` 软件版本，
  Boot 版本与主线版本在 `0x3100:04` / `0x3100:05`。

## 9. 台架实测（2026-10-15）

同一工装、同一节点号（node 1）分别接 R58 与 R48；gs_usb/SocketCAN `can0`（FD 1M/5M、
`dsample-point 0.812`），**总线上无 STM32 控制板**，全程只发 `0x080` 与 SDO 上传/分段请求

无错峰。无 SYNC 时零帧。

**控制板不是前置条件**：无控制板时 SDO 一问一答正常。`cerb_sdo_probe.py` 里"控制板必须在
总线上否则不应答"的旧记录作废，成因见 §10.3。

### 9.1 R48 节点 1 缩放核验（2026-10-22）

经单独授权，仅发送 SDO 上传请求，未写参数、未使能、未发送 MIT 运动目标：

- 身份为 `R48LITE_V2`，通信档位 `0x2540:00=4`。
- `0x2542~0x2546:00` 依次为 `314 / 314 / 2500 / 500 / 300`，与 §6 默认缩放一致；
  314 表示 **3.14**，不是数学常数 π。
- `0x6041:00=0x0060`（Switch on disabled）、`0x6061:00=0`。
- 位置限位 `-32768/+32768`、速度限值 `3325 rpm`、电流限值 `5000 mA`；
  方向 `0x2541:00=0`，保护开关 `0x2650:00=0`（保护开启）。

这是当前接入的单台 R48 的配置事实，不代表其他节点或 R58 已核验；设备设置的 5 A
不替代型号库 3.2 A 峰值安全约束。此轮未获得可用的连续反馈样本，静默原因未确认，
也未做带载、运动或控制频率验收。

## 10. 已知不一致与踩坑

### 10.1 中止码分层

设备对「对象不存在」与「子索引不存在」回不同中止码（`0x06020000` / `0x06090011`）。
模拟器若一律回后者，就复现不出对端的这一层语义。

### 10.2 厂家文档自身的错处

- **PR0002 §4.7 限位读写子索引写反**：表格里"读取正限位"用 `:01`、"读取负限位"用 `:02`，
  而它自己的设置行是正限位写 `:02`、负限位写 `:01`。以设置行为准（`motor_drive` 固件注释
  早于本文记录了同一结论）。
- **PR0002 §4.2 "关节型号 `0x1000`"**：实测 `0x1000:00` 是 4 字节整数设备类型 `0x00020192`，
  不是型号字符串。
- `0x2539` 是命令式对象（写保存码），只有 `:00` 存在；读 `:01/:02/:04` 回"子索引不存在"是
  正常的，不是缺陷。

### 10.3 标准帧 vs 扩展帧（一次真实踩坑）

用 python-can 4.x 写探针时注意：`Message(...)` 的 **`is_extended_id` 默认为 `True`**。同 ID
的扩展帧在总线上照样被设备 ACK（错误计数、bus-off、TEC 全为 0），所以"总线健康"不能证明
帧被对端理解；设备按 ID 过滤后静默忽略，现象是"发得出去、一条不回"。写探针时显式传
`is_extended_id=False`。判据：`candump -L` 里标准帧渲染为 `080##…`，扩展帧渲染为
`00000080##…`。

### 10.4 限位初值

文档称软件限位默认 ±32767，实测**两台独立设备**（R58 与 R48）都是 `-32768 / +32768`。
两台一致 ⇒ 判为出厂初值，文档的 `32767` 存疑（`0x607D` 经 `0x2539` 保存码持久化，
理论上可能是历史写入，但两台恰好相同的概率低）。

### 10.5 反馈帧 Iq 字段每码 20 mA，不是 1 mA（2026-10-21 真机实测）

按手册的 1 mA/码落地后，同一时刻的下发力矩与反馈力矩差 20 倍，且与设备自己的
`0x6078`（字典明确单位为 mA）对不上。R58（node 1）单轴扫描：固定使能 + 抱闸释放 +
kp=kd=0，逐档加码，每档 110+ 帧，`0x111` 的 τ 字段与 `0x301` 的 Iq 字段配对：

| 下发 τ（`T_max=300`） | Iq 码均值 | 每码 N·m | 电机转速 |
|---:|---:|---:|---:|
| −0.073 | −1.00 | — | 0 |
| 0.073 | 0.98 | 0.075 | 0 |
| 0.366 | 3.97 | 0.092 | 0 |
| 0.660 | 6.95 | 0.095 | 0 |
| 1.245 | 12.22 | 0.102 | 412 rpm |
| 2.418 | 23.91 | 0.101 | 1552 rpm |

最小二乘：`τ = 0.1015 × Iq码 − 0.014`（残差 < 半个码）。0.1015 N·m/码 ÷
（Kt 0.067 × 速比 101 × 效率 0.75）= **20.0 mA/码**，正好是整数。旁证：`0x6078`（峰值
电流）÷ √2 与 Iq 码 × 0.020 在两点上分别差 0.3% / 0.15% ⇒ 帧内 Iq 是**有效值**、
`0x6078` 是**峰值**。低端（<0.5 N·m）比值偏小只是 1 码 = 0.1 N·m 的量化，不是非线性。

落地：`kCerbCurrentCodeA`（`motor_drive`）、`MOTOR_PROTOCOL_CERB_CURRENT_CODE_A`
（固件）、`kCerbCurrentCodeA`（`motor_sim`）、`CERB_CURRENT_CODE_A`（`fdcan_motor_sim.py`）。
