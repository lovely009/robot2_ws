# full_body_robot STM32 位置 HIL

本轮只支持 MuJoCo 位置电机。STM32 下行位置目标通过 CAN 模拟电机后端，驱动主 MJCF 的 37 个实际输入轴；输出关节和十根连杆由原 MuJoCo 闭环解算。力矩电机另行添加。

## 模型与配置

- 原 `full_body_robot.xml`、位置执行器增益、惯量、限位、几何和闭环约束均保持原样。
- `motor_driver.simulation.yaml` 映射 37 个电机到 MJCF 输入轴。一对一传动用于电机输入坐标，腰/胯/肩/腕的机构运动由 MuJoCo 解算，不把双电机直接对应到两个输出关节。
- 主机使用独立的 `motor_driver.hil.yaml` 和 `transmissions.hil.yaml`，向工作台提供真实输出关节。六个耦合组通过共享 `ParallelLinkageTransmission` 转换位置、速度和力矩；几何直接取自同一 MJCF 的零位轴和球心。左腕 m13/m14 对应 `BN_LeftHand_roll/pitch`，右腕 m22/m23 对应右腕输出。
- `simulation_topology.yaml` 声明 `control_mode: position` 和主 MJCF 路径。
- `tools/build_hil_config.py` 从 CAD CSV 的 `SW Components` 提取型号，并记录文件 SHA256 及电机固定部分所属 link。固定件可能在输出关节的父 link，生成器显式绑定输入执行器名，避免依赖 XML 排序。
- CAD 中 R58 对应 ID 1–5、8–9、17–18、24–26、31–33；X25S-BZ153050 对应 13–14、22–23、30、37（`vaxor_2550`）；其余 16 台为 R48。

重新生成：

```bash
python3 ros2_ws/src/robot_description/models/full_body_robot/tools/build_hil_config.py
```

型号库提供协议缩放与静态参数。X25S 无峰值扭矩数据，仿真配置中保留额定值作为保守参数；本轮位置输入不据此改写主 MJCF 的位置执行器。

### 主机控制限位

`build_hil_config.py` 同时生成 `urdf/full_body_robot.hil.urdf`，供主机控制使用。每个输入轴的位置范围取模型位置限位与对应 MJCF 执行器范围的交集；原来作为辅助连续轴发布的电机输入使用 MJCF 的有限输入范围。几何、坐标、零位和被动关节保持同源。

速度取 `motor.yaml` 中对应型号的 `rated_speed_rad_s`。该字段已是减速器输出轴单位，HIL 电机输入为一对一映射，不再次除以减速比。力矩复用既有 HIL 型号峰值规格，缺少峰值时采用额定值。非法规格或空的位置范围交集使生成失败。`simulation_topology.yaml` 的 `command_*` 同步该交集，`hard_*` 保留 MJCF 原始输入范围。整机缺少 HIL 控制 URDF 时明确报错，其他模型维持原有独立 URDF 路径。主机控制和跟随控制器使用同一份 P/V/E 数据；启动时运动控制器保持 inactive，不写电机驱动板限位。

## 启动与反馈

工作台选择 MuJoCo、STM32 固件 HIL、full_body_robot 和已接线的 CAN 通道。各路模拟节点 ID 可以只覆盖部分电机，各通道的节点不能重复。主机按在线电机建立 HIL 控制子集会话，工作台允许对在线子集使能。关节目标使用该会话公布的 `control_groups`，并核对页面关节映射、反馈和 MCU 状态。物理 CAN 总线连接控制板和模拟电机后端。

完整耦合组接入输出关节控制；部分组保留已注册电机的输入轴控制，不宣称该组输出可以独立控制。此降级只由 HIL 配置中的 `hil_input_fallback` 开启，物理模型配置维持完整组校验。

位置 HIL 按模拟后端的实际注册表固定所有未注册电机输入轴。后端周期发布 `/robot_sim/registered_input_joints`（`JointState.name` 为输入轴名，时间戳为宿主时间），仿真启动或注册表超时时固定全部；撤销注册锁定当前角度，重新注册才释放该输入。未注册的 position actuator 关闭驱动增益，并在物理模型中施加固定约束。整个耦合组都未注册时，其输出也固定；部分组只固定缺失输入，允许机构闭环联动。此规则覆盖全部 ID，例如只注册 6–23 时，1–5 对应腰胯及 24–37 对应腿部都固定。

主机空闲且没有控制器认领命令接口时，反馈超时将导出无效测量并继续发送空命令心跳；新反馈到达后恢复关节状态。控制器认领命令接口后，反馈超时仍终止当前控制。设备故障、会话变化和非法报文继续进入故障处理。

桥接器收到首次 MCU 授权确认后，续租确认延迟时等待最近已发租约的本地到期点，该到期点受原 MCU 状态的 300 ms 生命周期约束。MCU 明确撤权、租约变更、状态断流或出现多个下行写入端时终止控制。首次使能仍需在 100 ms 内确认。

使能服务先核对调用方的 MCU 快照年龄、会话和停止屏障，再从主机受理时刻开始固定的 100 ms 执行期限。等待授权、排队和重试共用该期限。可靠 Status 的常规发布频率为 10 Hz，重要状态变化仍可按 20 ms 间隔发送；运动反馈为 50 Hz。

工作台单独启动的电机后端使用 `bridge_plant:=true`，连接 `/arm_position_controller/commands` 与 `/joint_states`；仿真 launch 本身不再启动第二个 CAN 后端。`position_input:=true` 让 MuJoCo 位置执行器接收按名字映射的位置数组。目标按现有执行器范围夹取；非法长度或非有限数的数组被拒绝，断流时锁定当前输入轴位置。HIL 会话不订阅原本的手动位置目标，避免两个控制源争用。

外部控制器入口继续直接启动原 Viewer 模型，原关节滑块和几何工作区仍可用。仿真电机配置不会替代真机 `motor_topology.yaml` 或将 `hardware_ready` 标记为 true。

## 验收

针对性检查包括 CAD 型号与输入轴映射、原模型不变、完整 launch 参数、独立后端的位置话题连接、数组映射及限幅、非法数据拒绝、原预览入口保留，以及隔离 ROS 域中的 37 台电机反馈和位置命令闭环。

2026-11-17 在 STM32 + 双 CAN 模拟后端 + MuJoCo 上验收，仅注册 6–23：

- 工作台提交左右腕 roll/pitch 正反目标，MCU 输入轴反馈、主机输出换算与 MuJoCo 输出一致，四轴最大到位误差为 0.000143 rad。
- 110 秒记录内，未注册的 19 个输入轴及整组缺失的 4 个腰胯输出，位置变化与反馈速度均为 0；主机健康状态持续正常，无电机故障。
- 撤销 m13 注册后，其输入轴固定在当前 -0.207526 rad，观测变化为 0；恢复注册后，18 台注册集合与完整腕部控制会话恢复。
- 针对未注册固定与注册表的 20 个回归用例通过，独立审查发现的安装文件和测试注册遗漏已修复。

本次修改部署在主机与仿真后端，未修改或重新烧录 MCU 固件。原始采样和汇总保存在 `robot2_ws-checkpoints/20261117-hil-output-registration/`。
