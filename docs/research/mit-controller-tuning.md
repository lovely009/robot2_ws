# MIT 控制（mini-cheetah 型）参数整定调研

调研日期：2026-08-12
调研问题：RP 关节电机与 25-30mm 腕部电机都使用 MIT 指令（Kp / Kd / 位置 / 速度 / 前馈力矩）控制。工程目前是不是还缺"参数整定 / MIT 调参"？缺什么？应该怎么做？

## TL;DR

1. **MIT 不是一个"固件模式"，而是一条 PD + 前馈控制律**：驱动器内部按
   `τ = Kp·(q_des − q) + Kd·(dq_des − dq) + τ_ff` 计算参考力矩/电流交给电流环。
   Kp 是刚度（位置增益）、Kd 是阻尼（速度增益）、τ_ff 是前馈力矩（重力/动力学补偿）。
   这是 RP 手册原文公式，也是 MIT Mini Cheetah 论文与多家厂商的通用做法。
2. **工程目前的 Kp/Kd 是占位值，不是整定结果**：RP `kp=30 / kd=1`（无依据），
   2530 `kp=0.008 / kd=1`（厂商建议初值）。仿真可以用理想值，**真机运行前必须逐关节整定**，
   否则会出现振荡、过流、MOS 过热甚至损坏。
3. **缺的不只是增益**：零位校准、保护阈值（MOS 温度/过流/过压）、故障状态上报、
   速度/位置模式参数、前馈力矩目前都没有接入真机链路——驱动层只解码出
   `JointState`（position/velocity/effort），把状态帧里的温度、电压、故障位都丢弃了。
4. **建议流程**：单电机台架安全验证 → 零位校准 → 厂商建议初值起步 → 小步增大 Kp（刚度）
   → 按临界阻尼配 Kd → 加前馈（重力/速度）→ 整机逐关节验证 → 把整定值写回 YAML，
   同时补齐故障上报与保护逻辑。

## 1. MIT 控制律与参数含义

### 1.1 控制公式（三种来源一致）

RP 系列协议手册（仓库 PDF，4.1.2.1 节）原文：

> 力矩指令 = Kp×(位置指令 – 反馈位置) + Kd×(速度指令 – 反馈速度) + 期望力矩

厂商 sitodrive 的 MIT 模式官方文档给出同一形式（输出为参考电流）：

> c_ref = Kp·(p_des − θ_m) + Kd·(v_des − dθ_m) + c_ff

MIT Mini Cheetah 论文（Katz / Di Carlo / Kim, ICRA 2019）在关节层使用相同的
"位置 + 速度 PD + 前馈力矩"结构，并把前馈力矩用于动力学补偿。

参数语义：

| 参数 | 含义 | 效果 |
|---|---|---|
| Kp | 位置比例系数（刚度） | 抵抗位置偏差；越大越"硬"，过大易振荡 |
| Kd | 速度比例系数（阻尼） | 抑制振荡；越大越"黏"，过大响应变慢 |
| τ_ff / c_ff | 前馈力矩/电流 | 抵消重力、摩擦与动力学惯量，不参与反馈 |

厂商文档明确警告：**Kp ≠ 0 而 Kd = 0 时阻尼为零，执行器会在目标位置附近振荡，不推荐**。

### 1.2 两种电机的参数单位差异（关键）

| 电机 | Kp 范围 | Kd 范围 | 前馈 | 物理含义 |
|---|---|---|---|---|
| RP 关节 | 0 ~ 500（12bit，默认阈值） | 0 ~ 10 | 期望力矩，±60 Nm | 公式直接输出 Nm，Kp 近似 Nm/rad、Kd 近似 Nm·s/rad |
| 25-30mm 腕部 | 0x0000~0xFFFF，`Kp=0.00001×码值`，建议初值 0.008 | `Kd=0.01×码值`，建议初值 1 | 前馈电流，`11/4096 A` | Kp/Kd 是**电流环增益换算值**：`Kp=kact×0.001115`、`Kd=kact×85.636`（rad/rad/s → A） |

注意 2530 的协议 Kp/Kd 不是"Nm/rad"刚度，而是"输入 rad / rad/s → 输出 A"的电流增益；
仿真 plant 已用 `wrist_kp_to_current_gain()` / `wrist_kd_to_current_gain()` 实现同一换算，
真机标定时应沿用厂商公式。RP 的 Kp/Kd 则直接是力矩刚度/阻尼，物理单位与阈值寄存器
（Pn3，默认 ±10 rad / ±60 rad/s / ±60 Nm / Kp 0..500 / Kd 0..10）一致。

## 2. 参数整定方法

### 2.1 通用流程（厂商与社区共识）

1. **电流模式验证**：Kp=0、Kd=0，只发前馈电流，确认电机能出力、方向正确、电流表与反馈一致。
2. **速度环验证**：Kp=0、Kd≠0，发目标速度，确认转速跟踪。
3. **位置环起步**：Kp 从小值开始（2530 用厂商建议 0.008；RP 建议从 kp≈5~10 起步），
   Kd 先给一个不为零的保守值，观察阶跃响应无明显超调。
4. **增大刚度**：逐步增大 Kp，直到跟踪误差满足要求；出现振荡就停止增大。
5. **配阻尼**：增大 Kd 抑制振荡；若响应过慢可回调 Kp。Kd 的工程参考值：
   `Kd ≈ 2·√(Kp·J_eff)`（临界阻尼），J_eff 为折算到电机轴的等效惯量（可从 URDF 质量/惯量估算）。
6. **加前馈**：速度前馈提升轨迹跟踪；重力补偿（上臂/前臂连杆）减少静态误差与电流消耗。

### 2.2 判据

- 阶跃响应无持续振荡、超调可接受；
- 电流峰值与 RMS 不超额定（2530 电流限制 11A；RP 0xB0 电流限制寄存器）；
- MOS/线圈温度可控（RP Pn4/Pn5 阈值）；故障寄存器无 Level2 触发。

### 2.3 模式选择

- 2530 支持 MIT / 速度 / 位置三模式，上电默认 MIT；**切模式必须先发送停止指令**（0x502+4N，Data0=0）。
- RP 支持 MIT / PP（规划位置）/ PV（规划速度），模式由 Pn08 配置；PP 模式可配置梯形加减速与位置增益 P。
- 上层 position controller 与 MIT 指令配合时，位置环刚度由 Kp 决定；若追求轨迹平滑，
  可改用 PP 模式（驱动器内做梯形规划）或保持 MIT + 上层规划平滑轨迹。

## 3. 本工程现状与缺口

| 环节 | 现状 | 说明 |
|---|---|---|
| 协议编解码 | ✅ 已实现且有单测 | RP 广播/2530 逐节点帧、字段换算、帧生成/解码测试 |
| MIT 增益 | ⚠️ 占位值 | RP 30/1、2530 0.008/1（厂商初值），无整定记录；YAML 注释已声明是仿真假设 |
| 零位校准 | ❌ 未实现 | 2530 校准指令 0006 + 0x503/0x703 校准帧；RP Pn08 零位配置 |
| 保护阈值 | ❌ 未配置 | RP Pn4/Pn5（MOS 温度/过流/过压）、0xB0（滤波/限流/力矩限制） |
| 故障上报 | ❌ 未解析 | 驱动只解出 JointState 三字段，丢弃 RP 状态帧 Byte5/6-7/8/9（温度/故障/电压）与 2530 状态帧电压/故障/电机状态/模式 |
| 模式切换与参数 | ❌ 未接入 | 2530 三模式、RP PP/PV 及其参数寄存器 |
| 前馈力矩 | ❌ 恒为 0 | `JointCommand.feedforward` 字段存在但上层未使用，重力/动力学补偿未实现 |
| 反馈超时 fail-fast | ✅ 已实现 | 激活重试 3×1s、运行期超时终止（ADR 0004） |

## 4. 后续怎么做（分阶段）

### 阶段 0：硬件准备与安全（真机前必做）

- 总线配置：RP 仲裁 1M / 数据 5M、采样点 75%；2530 仲裁 1M / 数据 4M、采样点 80%；两端 120Ω 终端电阻。
- 电源限流、硬件急停、示波器/电流钳准备；**先单电机台架，不装整机**。

### 阶段 1：基础验证与零位校准

- 验证反馈：位置/速度/电流/状态帧解析正确、方向与行程符合 URDF（±π 内）。
- 2530：`0005 → 0006` 校准，等待 10s，读 0x703 校准结果；
  RP：写 Pn08 零位配置 0x01，确认应答 0x01。

### 阶段 2：MIT 整定（单电机）

- 2530：Kp=0.008、Kd=1 起步；RP：Kp≈5~10、Kd≈2√(Kp·J_eff) 起步。
- 按第 2 节流程小步调参，记录每组增益的阶跃响应、电流峰值与温升。
- 整定通过后把数值写回 `motor_canfd.yaml`（`motor_types` 默认值 + 单电机覆盖），
  与 URDF 惯量/限位一并纳入拓扑一致性评审。

### 阶段 3：代码侧补齐（安全相关，建议优先）

- 扩展反馈解析：RP/2530 状态帧的温度、电压、故障位、电机状态/模式解析（R1/R3 范围）。
- 故障处理：Level1 告警上报、Level2 触发 fail-fast 停机（沿用 ADR 0004 语义）。
- 零位校准工具与模式切换/参数配置命令（作为 `motor_canfd_drive` 协议策略的扩展接口）。
- 前馈力矩接口：从上层接收重力/动力学补偿量，填入 `JointCommand.feedforward`。

### 阶段 4：整机验证

- 逐关节 → 单臂 → 双臂；确认限位、急停、反馈超时路径；用 `bus_override` 做 HIL 回环。
