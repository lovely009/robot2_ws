# 模拟电机后端多路支持

独立电机后端和 STM32 HIL 使用同一个多路入口。保持原单路 SocketCAN/SLCAN 参数兼容，新增 `multi` 传输和 `sim_channels_json` 通道列表。工作台以可编辑的通道行收集配置，ROS 服务透传同一份配置。

每路配置 MCU 总线索引（0..2）、传输类型（usbcanfd/socketcan/slcan）、端点及模拟节点 ID。只加载显式分配的模型节点，允许选择模型的部分电机；未分配的节点不创建，留空只开通道。`ids="*"` 加载未被其他路显式分配的模型节点，最多一路使用；显式分配不能重复或包含模型中不存在的 ID。运行期新增节点必须选路，已有节点命令按唯一 ID 路由。全局 ID 唯一约束来自 MCU 注册表，不能以跨路同 ID 模拟多个设备。

每路复用现有协议模拟器，拥有独立模型集合、SYNC 门控、SDO 状态和发送队列。一个主循环依次服务各路；被控对象桥只服务一次。创芯设备按 USB 物理地址选择，同一设备只打开一次、串行调用 SDK，两通道分别初始化；位率和终端参数在 InitCAN 之前设置。不修改 MCU 固件、型号参数或硬件标定。

启动先校验全部配置；任一路初始化失败时关闭已打开的通道和设备。运行期一路 I/O 故障只停该路，状态返回 failed/error，健康路继续服务；故障端点保持占有，避免同步关闭驱动阻塞其他路，在后端停止时统一释放。SLCAN 重开按逐条非阻塞配置步骤调度，等待间隔从实际写入完成时计算。停止时撤销后台读取、关闭控制 socket 和全部端点。资源锁阻止多个后端同时占用同一物理设备。USB SDK 使用用户安装的动态库，不将原厂二进制提交到仓库。

验收：跨路 SYNC、SDO、命令和反馈不会串路；共享 SDK 串行调用；配置缺失、重复路由、无效节点和初始化失败可观测且无资源泄漏；原单路测试继续通过；管理服务、launch 和工作台配置一致。测试优先用假 SDK、虚拟端点和现有针对性测试；本任务不执行真实电机动作。

Linux USB 初始化兼容：设备枚举后已经处于配置 1；原厂 SDK 再次设置同一配置会使实测 V2.13 固件停止返回 USB bulk IN，直到拔插 USB。`usbcanfd_compat.c` 通过 GET_CONFIGURATION 判断是否需要设置，保留原厂 SDK 的其余行为。`build_usbcanfd_compat.py` 将兼容库链接到用户安装的原厂库；Python 默认优先以本地作用域加载兼容库，显式指定库路径仍按原值使用。验证覆盖重复配置、真实变更、读取失败和动态符号作用域；硬件验收为读取设备信息、两通道连续打开/关闭及后端状态查询，不发送真实电机动作指令。
