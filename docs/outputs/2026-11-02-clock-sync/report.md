## 钟差的独立因果界

调用现有 `/motor/execute_config`，固定为 `ConfigRequest.CONFIG_KIND_SYSTEM_COMMAND` + `SystemCommand.COMMAND_REPORT`（4），只查询 MCU 当前内存参数视图；不触发 SDO、设零、保存或使能。

每个新 `(session_id, query_id, cursor=0)` 会在 MCU 重新填页并采时。记录最早 QUERY_INFO 的本机 DDS source_timestamp 为 t0、对应新 Info 的本机 DDS received_timestamp 为 t1、MCU snapshot_stamp 为 s。同查询重试仍保留最早 t0。只接受 DEVICE_PAGE / OK / clock_valid / 非零时间戳；新查询数量 60。

在 t0、t1 为本机时间且无跳变、MCU 采时因果位于二者之间的条件下，固件映射时钟相对主机的偏差区间为 `[s−t1, s+1ms−t0]`。1ms 是当前 millis() 采时量化余量；无需假定 USB 上下行延迟相等。

- 往返耗时最小 / 中位数 / P99 / 最大：2.343 / 5.980 / 10.848 / 10.932 ms。
- 全部 60 次各自区间的保守外包范围：[-1.074, 11.105] ms。
- 最紧单次区间（第 45 次，0 起算）：[-0.653, 2.689] ms。
- 探测阶段主机 wall−monotonic 变化范围 0.822 µs。

这些是约束区间，不是实测点误差或统计置信区间；全范围上限不能解读为已经观察到该数值的钟差。不能跨 10 秒校时变化将区间强行求交，也不能据此宣称 ±1ms 或亚毫秒精度。当前没有输出 XRCE 完整四时刻或独立硬件参考。

## 使用结论

短时同步健康及时间轴稳定性通过；可以沿用主机统一时间域对齐传感器、反馈和动作。当前证据不足以保证亚毫秒对齐或长时/重连可靠性。周期校时存在负修正，裸同步时间不能直接作为严格递增的唯一授权标识；后续请求应由主机统一生成会话内唯一标识，并保留真实源时间做 TTL 校验。

## 范围与复现

- 180 秒阶段只有 ROS 订阅；另 60 次 REPORT 均只读。未写控制/保护参数、未烧录、未代发使能或运动、未重启服务。
- 中途通过 ST-LINK 仅连接后读取 SCB_CCR 并退出，未暂停、复位或写内存；D-Cache 已开启，因此没有把 SWD 读取的缓存后备 RAM 当作实时真值。
- 未覆盖断线重连、满负载运动、长时温漂或时钟计数回绕边界。
- `collect.py`、`probe.py` 和 `analyze.py` 为本次采集脚本；`samples.csv.gz`、`offset_bounds.csv`、`capture.json`、`summary.json` 为原始数据和统计。脚本运行需 source ROS 和两个工作区环境。
- 重算已有数据先执行 `gzip -dk samples.csv.gz`；`analyze.py` 不访问设备或发送请求。
