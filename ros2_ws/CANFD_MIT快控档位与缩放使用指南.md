# CAN FD MIT 快控档位与缩放使用指南（默认参数）

## 1. 文档目的

本文用于指导上位控制器配置 CAN FD 通信档位，并正确编码、解码 MIT 快控命令。文档不针对具体执行器型号，只说明协议通用规则和固件默认参数。

适用前提：设备支持 CANopen 维护对象 `0x2540`、`0x2542~0x2546`，并启用了 CAN FD 自定义 MIT 快控协议。

> 设备 Flash 中的当前值优先于本文默认值。首次连接、更换设备、升级固件或恢复参数后，必须逐节点读取档位和五项缩放，不能只读取一台设备后推断其他节点。

> 安全提示：修改档位会导致当前 CAN 通信中断；错误的 MIT 缩放可能直接产生满量程位置、速度或力矩命令。修改和首次验证时必须使伺服失能、停止 MIT 使能帧、固定机械负载，并确保急停可用。

## 2. 默认档位和默认缩放

### 2.1 CAN FD 默认档位

| 项目 | 默认值 |
| --- | --- |
| CAN 速率档位 `0x2540:00` | `4` |
| 帧格式 | CAN FD，11 bit 标准帧 |
| 仲裁域速率 | `1 Mbit/s` |
| 数据域速率 | `5 Mbit/s` |
| BRS | 启用 |

档位枚举如下：

| `0x2540:00` | CAN 模式 | 仲裁域 | 数据域 | BRS |
| ---: | --- | ---: | ---: | --- |
| `0` | Classic CAN | 500 kbit/s | — | — |
| `1` | Classic CAN | 1 Mbit/s | — | — |
| `2` | CAN FD | 1 Mbit/s | 1 Mbit/s | 关闭 |
| `3` | CAN FD | 1 Mbit/s | 2 Mbit/s | 启用 |
| `4` | CAN FD | 1 Mbit/s | 5 Mbit/s | 启用 |

### 2.2 MIT 命令默认缩放

| 物理量 | CANopen 对象 | raw 位宽 | 默认物理范围 |
| --- | --- | ---: | ---: |
| 目标位置 `q_des` | `0x2542:00` | 16 bit | `-3.14~+3.14 rad` |
| 目标速度 `dq_des` | `0x2543:00` | 12 bit | `-3.14~+3.14 rad/s` |
| 刚度 `Kp` | `0x2544:00` | 12 bit | `0~2500 Nm/rad` |
| 阻尼 `Kd` | `0x2545:00` | 12 bit | `0~500 Nm·s/rad` |
| 前馈力矩 `tau_ff` | `0x2546:00` | 12 bit | `-300~+300 Nm` |

其中，位置和速度对象的存储单位为 `0.01`：

```text
0x2542 = 314  -> Pmax = 3.14 rad
0x2543 = 314  -> Vmax = 3.14 rad/s
```

速度单位必须使用 `rad/s`，不能把 `rpm`、`度/s` 或 12 bit raw 数值直接当作 `rad/s`。常用换算为：

```text
rpm   = rad/s × 60 / (2π)
rad/s = rpm × 2π / 60
```

默认分辨率：

| 物理量 | 默认每 LSB 对应值 |
| --- | ---: |
| 位置 | `6.28 / 65535 = 0.0000958267 rad/LSB` |
| 速度 | `6.28 / 4095 = 0.00153358 rad/s/LSB` |
| Kp | `2500 / 4095 = 0.610501 Nm/rad/LSB` |
| Kd | `500 / 4095 = 0.122100 Nm·s/rad/LSB` |
| 前馈力矩 | `600 / 4095 = 0.146520 Nm/LSB` |

通信缩放只定义 raw 与物理量之间的换算关系，不等于设备最终的位置、速度、力矩或电流保护限值。

## 3. 读取和修正 CAN 通信档位

CANopen SDO 使用：

```text
发送 CAN ID = 0x600 + NodeID
响应 CAN ID = 0x580 + NodeID
数据长度 = 8 字节
```

以下示例均以 `NodeID=1` 为例。

### 3.1 读取当前档位

```text
Tx ID:   0x601
Tx Data: 40 40 25 00 00 00 00 00
```

默认档位 `4` 的响应应为：

```text
Rx ID:   0x581
Rx Data: 43 40 25 00 04 00 00 00
```

响应 Byte4~Byte7 是小端 `int32`。如果响应 Byte0 为 `0x80`，表示 SDO abort，Byte4~Byte7 是 abort code，不能当作档位值。

### 3.2 写入默认档位 4

```text
Tx ID:   0x601
Tx Data: 23 40 25 00 04 00 00 00
```

写请求被接收时通常响应：

```text
Rx ID:   0x581
Rx Data: 60 40 25 00 00 00 00 00
```

注意事项：

1. `0x2540` 是独立的启动通信参数，不需要再写 `0x2539` 保存。
2. 新档位在重新上电或重新启动后生效。
3. 重新启动后，上位机必须同步切换到 CAN FD 1M/5M，否则将无法继续通信。
4. 改错档位可能导致设备暂时失联，操作前必须记录原值并准备对应档位的回退工具。

## 4. MIT 8 字节 raw payload

MIT raw payload 固定为 8 字节：

| 字节 | 位域 |
| --- | --- |
| Byte0 | `position_raw[15:8]` |
| Byte1 | `position_raw[7:0]` |
| Byte2 | `velocity_raw[11:4]` |
| Byte3 高4位 | `velocity_raw[3:0]` |
| Byte3 低4位 | `kp_raw[11:8]` |
| Byte4 | `kp_raw[7:0]` |
| Byte5 | `kd_raw[11:4]` |
| Byte6 高4位 | `kd_raw[3:0]` |
| Byte6 低4位 | `torque_raw[11:8]` |
| Byte7 | `torque_raw[7:0]` |

解包公式：

```c
position_raw = ((uint16_t)data[0] << 8) | data[1];
velocity_raw = ((uint16_t)data[2] << 4) | (data[3] >> 4);
kp_raw       = ((uint16_t)(data[3] & 0x0F) << 8) | data[4];
kd_raw       = ((uint16_t)data[5] << 4) | (data[6] >> 4);
torque_raw   = ((uint16_t)(data[6] & 0x0F) << 8) | data[7];
```

打包公式：

```c
data[0] = (uint8_t)(position_raw >> 8);
data[1] = (uint8_t)position_raw;
data[2] = (uint8_t)(velocity_raw >> 4);
data[3] = (uint8_t)(((velocity_raw & 0x0F) << 4) | (kp_raw >> 8));
data[4] = (uint8_t)kp_raw;
data[5] = (uint8_t)(kd_raw >> 4);
data[6] = (uint8_t)(((kd_raw & 0x0F) << 4) | (torque_raw >> 8));
data[7] = (uint8_t)torque_raw;
```

所有多字节和跨字节字段均按上述大端位序打包，不能直接复制 CPU 小端结构体内存。

## 5. raw 与物理量换算

先读取设备的五项量程，并定义：

```text
Pmax  = 0x2542 × 0.01 rad
Vmax  = 0x2543 × 0.01 rad/s
Kpmax = 0x2544 Nm/rad
Kdmax = 0x2545 Nm·s/rad
Tmax  = 0x2546 Nm
```

### 5.1 驱动器解码公式

```text
q_des  = position_raw / 65535 × (2 × Pmax) - Pmax
dq_des = velocity_raw / 4095 × (2 × Vmax) - Vmax
Kp     = kp_raw / 4095 × Kpmax
Kd     = kd_raw / 4095 × Kdmax
tau_ff = torque_raw / 4095 × (2 × Tmax) - Tmax
```

### 5.2 上位机编码公式

```text
position_raw = round((q_des + Pmax) / (2 × Pmax) × 65535)
velocity_raw = round((dq_des + Vmax) / (2 × Vmax) × 4095)
kp_raw       = round(Kp / Kpmax × 4095)
kd_raw       = round(Kd / Kdmax × 4095)
torque_raw   = round((tau_ff + Tmax) / (2 × Tmax) × 4095)
```

编码前必须将物理量限制在对应范围内，编码后还必须将 raw 限制到对应位宽：位置 `0~65535`，其余字段 `0~4095`。

位置、速度和前馈力矩使用带中点偏置的映射；Kp、Kd 使用从零开始的无符号映射。设备方向参数可能改变位置、速度和力矩的正负方向，因此方向必须在低增益、低速度条件下实机确认。

### 5.3 raw 不是物理值

例如默认速度量程下：

```text
velocity_raw = 0x555 = 1365
dq_des = 1365 / 4095 × 6.28 - 3.14
       = -1.04667 rad/s
       ≈ -10.0 rpm
```

所以，不能把 `0x555` 或十进制 `1365` 直接解释为 `1365 rad/s`、`1365 rpm`，也不能把期望 rpm 直接填入 12 bit 字段。

## 6. 零命令必须编码到中点

默认量程下：

```text
q_des = 0 rad    -> position_raw ≈ 32768 = 0x8000
dq_des = 0 rad/s -> velocity_raw ≈ 2048  = 0x800
tau_ff = 0 Nm    -> torque_raw ≈ 2048    = 0x800
Kp = 0           -> kp_raw = 0
Kd = 0           -> kd_raw = 0
```

由于 `65535` 和 `4095` 是奇数，中点不能精确表示零；四舍五入产生的小于 1 LSB 的偏差属于正常量化误差。

以下情况不是零命令：

```text
position_raw = 0 -> q_des = -Pmax
velocity_raw = 0 -> dq_des = -Vmax
torque_raw = 0   -> tau_ff = -Tmax
```

如果 8 字节 MIT payload 的五个 raw 字段全部为零，固件还会将其判定为无效命令并丢弃。不要使用“8 字节全零”表示零位置、零速度或零力矩。

## 7. MIT 快控 CAN FD 入口

### 7.1 单轴入口

```text
CAN ID = 0x110 | NodeID
数据长度 = 12 字节（CAN FD DLC 编码 = 9）
```

| 字节 | 内容 |
| --- | --- |
| Byte0 | 控制字 |
| Byte1~8 | MIT 8 字节 raw payload |
| Byte9~11 | 保留，发送时填 0 |

控制字：

| 位 | 含义 |
| --- | --- |
| bit7 | 使能 |
| bit6 | 释放抱闸 |
| bit5 | 清故障 |
| bit4~bit1 | 控制模式，MIT 固定为 `6` |
| bit0 | 保留 |

常见的“使能 + 释放抱闸 + MIT 模式”控制字为：

```text
0x80 + 0x40 + (6 << 1) = 0xCC
```

清故障位只应按需要产生复位事件，不应在每帧持续置位。

CAN ID 使用按位或 `|`，不是普通加法。为避免 `0x110 | NodeID` 发生 ID 重叠，单轴快控节点建议使用唯一的 `NodeID=1~15`。

### 7.2 多轴入口

```text
CAN ID = 0x210
数据长度 = 64 字节（CAN FD DLC 编码 = 15）
最多 6 个 MIT 轴
```

| 字节 | 内容 |
| --- | --- |
| Byte0~8 | Slot0：控制字 + 8 字节 MIT payload |
| Byte9~17 | Slot1 |
| Byte18~26 | Slot2 |
| Byte27~35 | Slot3 |
| Byte36~44 | Slot4 |
| Byte45~53 | Slot5 |
| Byte54~55 | 保留 |
| Byte56~61 | Slot0~Slot5 对应的 NodeID |
| Byte62~63 | 保留 |

设备先在 Byte56~61 查找自己的 NodeID，再按相同 Slot 下标读取对应的 9 字节命令。

### 7.3 独立 8 字节入口

```text
CAN ID = 0x500 + NodeID
数据长度 = 8 字节
```

该入口不带控制字。使用前必须先把 `0x6060:00` 设置为模式 `6`，使驱动器进入 Operation Enabled，并按设备要求释放抱闸。8 字节 payload 本身不会设置模式、使能、释放抱闸或清故障。

### 7.4 candump 格式

在 candump CAN FD 文本中：

```text
210##5<64字节payload>
```

`##` 后的第一个十六进制字符是 CAN FD flags，不属于 payload。解析前必须先移除 flags，否则整帧会错半个字节。

## 9. 恢复默认缩放并保存

修改前必须：

1. 使伺服失能并停止发送 MIT 使能帧。
2. 逐节点读取并记录原来的 `0x2542~0x2546`。
3. 确认上位控制器会同步使用新缩放。

恢复通用默认缩放，以 `NodeID=1` 为例：

| 操作 | Tx Data |
| --- | --- |
| 写位置量程 314 | `23 42 25 00 3A 01 00 00` |
| 写速度量程 314 | `23 43 25 00 3A 01 00 00` |
| 写 Kp 量程 2500 | `23 44 25 00 C4 09 00 00` |
| 写 Kd 量程 500 | `23 45 25 00 F4 01 00 00` |
| 写前馈力矩量程 300 | `23 46 25 00 2C 01 00 00` |
| 保存缩放：写 `0x2539=1` | `23 39 25 00 01 00 00 00` |

以上 Tx CAN ID 均为 `0x600 + NodeID`。32 bit 写入值采用小端格式。写入请求被接收的 SDO 响应通常为：

```text
60 <索引低字节> <索引高字节> 00 00 00 00 00
```

收到 `0x60` 只表示 SDO 请求被接收，不等于已经证明后台校验和 Flash 保存完成。推荐验证流程：

1. 写入所有需要修改的缩放。
2. 写 `0x2539:00=1`。
3. 等待至少 `500 ms`，重新读取 `0x2542~0x2546`。
4. 重新上电后再次逐项读取。
5. 上位机用读回值重新建立编码系数。
6. 本地执行“编码→解码”自检，误差不得超过 1 LSB。
7. 先使用低 Kp、低 Kd、零前馈力矩做低风险实机验证。

如果只需修正 MIT 缩放，不要执行 `0x1011:03="load"`；该命令可能恢复整套应用默认参数，而不只是 MIT 缩放。

## 10. 客户端修正检查清单

- [ ] 上位机档位设置为 CAN FD 1M/5M，并启用对应 BRS 配置。
- [ ] 读取 `0x2540:00`，确认设备当前档位为 `4`。
- [ ] 逐节点读取 `0x2542~0x2546`，确认五项缩放与上位机完全一致。
- [ ] 速度统一使用 `rad/s`，需要 rpm 时先按 `2π/60` 换算。
- [ ] 位置、速度、前馈力矩的零点编码在 raw 中点，而不是 raw 0。
- [ ] Kp、Kd 从 raw 0 开始编码，不做正负偏置。
- [ ] 跨字节字段按协议位域打包，不直接发送小端结构体。
- [ ] 编码前做物理量限幅，编码后做 raw 位宽限幅。
- [ ] 单轴帧使用 `0x110 | NodeID` 和 12 字节数据。
- [ ] 多轴帧使用 `0x210`、64 字节数据，并核对 Slot 与 NodeID 列表。
- [ ] 改缩放后写 `0x2539=1`，等待保存并重新上电复核。
- [ ] 改通信档位后重新启动设备，并同步切换上位机 CAN 档位。

## 11. 默认参数汇总

```text
CAN 档位：4
CAN 模式：CAN FD
仲裁域：1 Mbit/s
数据域：5 Mbit/s
BRS：启用

位置：±3.14 rad
速度：±3.14 rad/s
Kp：0~2500 Nm/rad
Kd：0~500 Nm·s/rad
前馈力矩：±300 Nm
```

最终原则：设备端与上位机必须使用同一档位、同一组缩放和同一套位域打包规则。任何一项不一致，同一 CAN payload 都会被解释成不同的物理命令。
